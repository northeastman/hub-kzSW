# 会话记忆（Session Memory）功能改动点总结

> 项目：`week12/react_financial_agent`
> 特性分支：`feat: session memory`（合并提交 `51f28cf`）
> 一句话概述：在不改动原有 ReAct 循环的前提下，外挂一层"滚动摘要记忆"，让 Function Calling 版 Agent 具备多轮上下文记忆能力。

---

## 一、设计思路

核心原则是 **不重写 ReAct 循环，只在外层加一层记忆**：

1. **复用而非重写**：`run_with_memory()` 直接复用 `react_function_calling.run()`，改 `run()` 不会让记忆逻辑走样。
2. **滚动摘要（Rolling Summary）**：每轮问答结束后调用模型，把「旧摘要 + 本轮问答」压缩成一段简短摘要，覆盖存回，而不是堆叠全部历史。好处是上下文长度可控。
3. **前缀注入**：因为 `run()` 只接收一个 `question` 字符串，记忆通过"把摘要拼进问题前缀"的方式注入——这是不改 `run()` 前提下唯一的注入口。
4. **进程内存储**：记忆存在进程内 `dict`，重启即丢失，适合教学演示，无需数据库。

## 三、后端核心：`src/session_memory.py`（新增）

### 1. `SessionMemory` 类 —— 进程内会话记忆

维护 `session_id -> 滚动摘要文本` 的字典，提供三个方法：

- **`get(session_id)`**：取该会话当前摘要，无则返回空串。
- **`update(session_id, question, answer)`**：调模型把「旧摘要 + 本轮问答」压缩成新摘要覆盖存回；**模型调用失败时保留旧记忆**（`try/except`），不影响本轮答案。
- **`clear(session_id)`**：清空指定会话记忆，对不存在的 id **幂等**（`pop(..., None)`）。

摘要压缩用专门的 `SUMMARY_SYSTEM_PROMPT`，要求保留关键事实（公司、股票代码、财务指标、数值结论、用户关注点），去掉寒暄和工具调用细节。

### 2. 模块级单例 `_MEMORY`

`serve.py` 与 CLI **共用同一份记忆**，保证 Web 和命令行行为一致。

### 3. `run_with_memory()` 生成器 —— 记忆版 ReAct 循环

四个步骤：
```
取会话摘要 → 拼进问题前缀 → 复用 run() 逐步透传 → 结束后更新摘要
```
- 有记忆时：`augmented = f"已知对话背景：{memory}\n\n用户当前问题：{question}"`
- 无记忆时：直接透传原始问题，不拼前缀
- yield 的 dict 格式与 `run()` **完全一致**，因此 serve / 前端可无差别复用现有渲染逻辑
- 循环结束后用**原始 question（不含前缀）**+ 本轮答案更新摘要

### 4. CLI 多轮 REPL 演示

`__main__` 提供交互式命令行：输入 `exit` 退出、`clear` 清空记忆，复用 FC 版的彩色输出风格。

## 四、服务层：`src/serve.py`（修改）

1. **`QueryRequest` 模型**：新增 `session_id: str = "default"` 字段。
2. **`_stream_react()`**：增加 `session_id` 参数与 `mode == "memory"` 分支，用闭包 `_make_gen()` 统一三种模式的生成器构造方式，避免 worker 里写死调用。
3. **新增 `POST /query/memory`**：流式 SSE 返回带记忆的每步结果。
4. **新增 `POST /session/clear`**：接收 `ClearRequest`，调用 `clear_session()` 清空指定会话，返回 `{"status": "cleared"}`。

---

## 五、前端：`index.html`（修改）

1. **会话 id 生成**：页面加载时生成唯一 `sessionId`（`web-<random>-<perf>`），**刷新页面 = 新会话、记忆清空**。
2. **新增"带记忆 (FC)"模式按钮**：`data-mode="memory"`。
3. **新增"🧹 清空记忆"按钮**：仅 memory 模式下显示（`setMode` 中控制），点击调用 `/session/clear` 并清空步骤区。
4. **发送逻辑差异化**：
   - memory 模式在 payload 中带上 `session_id`。
   - memory 模式**保留历史步骤卡片**（便于观察上下文累积），其余模式清空。
5. **Final 卡片实现标注**：新增 `memory: 'Function Calling + 记忆'` 映射。

### `tests/test_session_memory.py`（9 个用例）
- 空会话返回空串

- **模型失败时保留旧记忆**
- `run_with_memory` 有记忆时注入前缀、无记忆时透传原始问题

- `/query/memory` 流式返回步骤（打桩 `run_with_memory`）
- `/session/clear` 返回 `{"status": "cleared"}` 且传递正确 session_id

## 七、值得注意的教学取舍

1. **前缀注入是自觉的代价**：不改 `run()` 的约束下，把摘要拼进问题是唯一注入口，牺牲了一点"优雅"换取"改 run 不影响记忆"的解耦。
2. **滚动摘要 vs 全量历史**：用摘要压缩控制上下文长度，代价是可能丢失细节；适合演示，生产可换成向量检索或分级记忆。
3. **进程内存储**：重启丢失，无持久化；生产需换 Redis / DB。
4. **记忆更新失败降级**：摘要更新失败只告警、保留旧记忆，保证本轮答案不受影响。
