## 一、先划定"已讲基准线"

课程 week16 讲的是 2025Q4–2026 这批"MLA + 稀疏/线性注意力 + 细粒度 MoE"的国产旗舰。它们的结构骨架（取自本地 config）：

| 已讲模型 | 参数/激活 | 层数·隐藏维 | 注意力 | FFN/MoE | 长上下文手段 |
|---|---|---|---|---|---|
| **Qwen3.6-27B** (`qwen3_5`) | 27B **Dense** | 64 / 5120 | **混合**：3×线性(Gated DeltaNet) + 1×全注意力(Gated Attn, GQA24/4) | Dense FFN 17408 | 部分RoPE(0.25)+mRoPE，262K→1M |
| **DeepSeek-V4-Pro** (`deepseek_v4`) | MoE 6/384 | 61 / 7168 | **MLA + DSA 稀疏索引**(index_topk=1024)，滑窗128 | 384 专家选 6，1 共享 | YaRN(→1M)+逐层KV压缩，FP4 专家 |
| **Kimi-K3** (`kimi_linear`) | MoE 16/896 | 93 / 7168 | **Kimi Linear(KDA) + 每4层 MLA**(NoPE) | 896 专家选 16，2 共享 | 线性注意力常量状态，1M |
| **GLM-5.2** (`glm_moe_dsa`) | MoE 8/256 | 78 / 6144 | **MLA + DSA 索引**(index_topk=2048) | 256 专家选 8，1 共享，前3层Dense | 1M |

**已讲基准的共同"套路"**：① 注意力都在想办法把 KV 从 O(n²) 降下来（MLA 低秩压缩 / DSA 稀疏 / KDA 线性）；
② FFN 基本都是**细粒度 MoE + 共享专家**；③ 普遍带 **MTP（多 token 预测）** 头做投机解码。

下面调研的 4 个"没讲的"模型，正好在这几个维度上给出了**不同的技术下注**，形成鲜明对照。

## 二、没讲的模型①：Qwen3.8-27B —— 用户点名的这个

**一句话**：它和课上讲的 **Qwen3.6-27B 是同一套结构**（`Qwen3_5ForConditionalGeneration`），
**结构几乎没变，进化发生在训练/数据，而非架构**。这是它最值得说的"结构特点"。

**结构要点（config 实证）**：

- **Dense 而非 MoE**：27B 参数全激活，没有专家路由。在一众 MoE 旗舰里，它走的是"稠密小模型 + 高效注意力"路线，主打**单卡/桌面级本地部署**。
- **混合注意力（核心亮点）**：64 层 = 16 组 `3×(Gated DeltaNet→FFN) + 1×(Gated Attention→FFN)`。
  - **48 层线性注意力（Gated DeltaNet）**：类 Mamba 的门控 delta 规则，`value_heads=48 / key_heads=16`，head_dim 128，短卷积核 4，**常量大小的循环状态**——推理时 KV 不随序列增长。
  - **16 层全注意力（Gated Attention）**：GQA `24/4`，head_dim 256，`attn_output_gate=true`（输出门控），**部分 RoPE（只旋转 64/256 维）**，其余维度不加位置编码。
- **MTP 头**：`mtp_num_hidden_layers=1`，支持投机解码，官方称吞吐提升 15–25%。
- **原生多模态**：`mRoPE`（时/高/宽三段 11/11/10）+ 视觉编码器（depth 27、patch 16、spatial_merge 2），图像/视频直接进嵌入空间（非 LLaVA 式 adapter 外挂）。
- **上下文**：262,144 原生，可扩到 1,000,000。

**与已讲 Qwen3.6-27B 的差异**：`hidden/层数/注意力布局/专家配置` 全部一致，仅 `transformers_version`（5.8.0.dev0 vs 4.57.1）不同。
→ **结论：Qwen3.8 是 Qwen3.6 的"训练迭代版"，是"同结构、换数据/对齐"的典型，说明 Qwen 团队已把 GDN 混合架构当成稳定底座。**

## 三、没讲的模型②：gpt-oss-120b —— OpenAI 的开源权重

**一句话**：西方阵营的 MoE，用 **滑动窗口 + 注意力汇聚(attention sink) + 原生 MXFP4** 解决效率，路线和国产的 MLA/DSA 完全不同。

**结构要点（config 实证）**：

- **MoE**：128 专家 / 每 token 选 4；36 层，hidden 2880，head_dim 64，GQA `64/8`。
- **注意力：滑动窗口 + 全注意力交替**：`layer_types` 逐层在 `sliding_attention`（窗口=128）与 `full_attention` 之间交替。**不做 MLA、不做低秩压缩、不做 DSA 稀疏索引**——直接靠"一半层只看最近 128 token"来省 KV。
- **Attention Sink（汇聚头）**：每个注意力头带一个可学习的偏置"沉没位"，稳定长序列 softmax（gpt-oss 的标志性设计）。
- **原生 MXFP4 量化**：专家权重直接以 MXFP4 存储训练/发布，`self_attn / router / embed / lm_head` 保留高精度——这是它能"120B 塞进单卡"的关键。
- **RoPE + YaRN**：rope_theta 150000，原生 4096 经 YaRN factor 32 扩到 131,072。

**对照价值**：同样是"省 KV"，gpt-oss 选**滑窗+sink**（工程简单、生态成熟），
而 DeepSeek/GLM 选 **MLA+DSA**（压缩+稀疏、极致省显存）。两条路线的哲学差异很典型。

## 四、没讲的模型③：MiniMax-M2 —— "反潮流"的一个

**一句话**：它是最有意思的**反例**——**主动放弃了线性注意力，全层回归标准全注意力**，直接打脸"线性注意力是未来"的叙事。

**结构要点（技术报告）**：

- **规模**：229.9B 总参 / **9.8B 激活**（极稀疏 MoE）；62 层，hidden 3072，vocab 200064，训练 29.2T token，上下文 192K。
- **MoE**：256 个细粒度专家 / 每 token 选 8（相比上一代 MiniMax-Text-01 的"32 专家 top-2"大幅细粒度化）。
- **注意力：全层标准多头注意力**。上一代 Text-01 是 **Lightning Attention（线性）+ 全注意力 7:1 混合**，而 **M2 把线性注意力全部去掉了**。官方解释：在"推理 / 代码 / Agent"这类真实生产任务上，**没有任何一种高效注意力变体能稳定匹配全注意力的质量**（"No Free Lunch"）。

**对照价值**：Qwen3.8 / Kimi-K3 重仓**线性注意力混合**，MiniMax-M2 却**用同门上一代验证后退回全注意力**。
→ 说明 2026 年"线性/稀疏注意力 vs 全注意力"仍是**未定之争**，取舍取决于目标任务（长上下文吞吐 vs 复杂推理质量）。这是本次调研最有价值的"结构分歧点"。

## 五、没讲的模型④：Llama 4 Scout —— iRoPE 的长上下文玩法

**一句话**：靠 **iRoPE（RoPE 层与 NoPE 层交替）+ 分块局部注意力**，把上下文干到 **1000 万 token**，路线又和上面三家都不同。

**结构要点（官方博客/技术资料）**：

- **MoE**：Scout = 16 专家 / 17B 激活；Maverick = 128 专家(+1 共享) / 17B 激活。
- **iRoPE（核心亮点）**：每 4 层里 3 层用 **RoPE + 分块局部注意力（chunk=8192，只看最近 8K）**，第 4 层用 **NoPE（完全不加位置编码）+ 全局注意力**。
  - 直觉：NoPE 层把 token 当"无序集合"处理，**反而在超长距离上泛化更好**；RoPE 分块层负责局部秩序。二者交替 → 局部有序 + 全局可达。
- **NoPE 层温度缩放**：长序列时对 NoPE 层注意力做温度调节，抑制注意力分数衰减。
- **QK-Norm** + 原生多模态**早融合（early fusion）**：文本与视觉 token 在预训练阶段就进同一序列。
- **上下文**：Scout 10M。

**对照价值**：解决长上下文，DeepSeek/GLM 用**稀疏索引(DSA)**、Qwen/Kimi 用**线性注意力**、gpt-oss 用**滑窗+sink**，
而 Llama 4 用 **NoPE 交替 + 分块**——同一个问题，**四种完全不同的结构答案**。

## 七、调研结论：一张"技术下注地图"

把 8 个模型放在一起看，**2026 年开源大模型的结构演进，本质是围绕两件事的不同下注**：

**1. 如何把注意力从 O(n²) 降下来（长上下文效率）—— 出现了 4 条互不相同的路线：**
- **线性注意力混合**（Qwen3.8 的 Gated DeltaNet、Kimi-K3 的 KDA）：常量状态，吞吐最优；
- **稀疏注意力**（DeepSeek-V4 / GLM-5.2 的 DSA 索引）：只算 top-k，兼顾质量与显存；
- **滑窗 + 汇聚**（gpt-oss）：工程最简单，生态最成熟；
- **NoPE 交替 + 分块**（Llama 4 iRoPE）：靠"去位置编码"换超长外推；
- **以及反对派**（MiniMax-M2）：认为高效注意力都损质量，**干脆全用全注意力**。

**2. FFN 侧几乎全面 MoE 化**：除 Qwen3.8 坚持 Dense（为本地部署）外，其余都是"细粒度专家 + 共享专家 + 极低激活比"，
用总参数换容量、用低激活换推理成本；辅以 **MTP** 投机解码进一步提吞吐。

**给学习者的一句话总结**：
> 已讲的 DeepSeek/Kimi/GLM/Qwen 代表了"**MLA/线性/稀疏 + 细粒度 MoE**"这一主流范式；
> 而没讲的这几个恰好补齐了**边界与反例**——Qwen3.8 证明"同结构靠训练迭代"、gpt-oss 展示"滑窗+MXFP4 的工程路线"、
> Llama 4 给出"iRoPE 的长文本解法"、MiniMax-M2 则提醒我们"**高效注意力仍是未定之争，全注意力并未过时**"。
> 看懂这张"技术下注地图"，比记住任何单个模型的参数都重要。
