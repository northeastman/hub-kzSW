# Log Stats 日志统计分析

本 skill 用于对一个服务器或应用产生的日志文件进行统计分析。它会读取用户提供的
日志文件路径，然后对文件中的每一行进行解析，统计出各种有用的信息，最后把这些信息
汇总成一份人类可读的文本报告打印出来，方便用户快速了解日志的整体情况、排查问题。

## 触发场景

当用户说出类似下面这些话的时候，就应该触发并使用本 skill：

- "帮我分析一下这个日志文件"
- "统计一下 app.log 里各级别日志有多少条"
- "看看这个 log 文件里最多的错误是什么"
- "这个日志哪个小时的请求量最多"
- "帮我看看 server.log 的整体概况"
- "分析 /var/log/app.log"
- "这个日志有多少条 ERROR？"
- "帮我做一份日志统计报告"

## 日志格式说明

本 skill 假定日志文件是最常见的那种格式，即每一行都以一个时间戳开头，
后面紧跟着日志级别，再后面是具体的日志内容。一个典型的日志行看起来是这样的：

```
2026-08-06 10:23:45 INFO  User login succeeded for user_id=1024
2026-08-06 10:23:46 WARN  Cache miss for key=session_88
2026-08-06 10:23:47 ERROR Database connection timeout after 30s
2026-08-06 10:23:48 DEBUG Entering function handle_request()
```

也就是说，每一行的结构是：

- 前面 10 个字符是日期，格式为 `YYYY-MM-DD`
- 一个空格
- 接着 8 个字符是时间，格式为 `HH:MM:SS`
- 一个空格
- 接着是日志级别，可能是 DEBUG、INFO、WARN、ERROR 中的一个
- 再一个空格（或多个空格）
- 剩下的全部内容是这一行日志的具体信息

## 执行流程

请严格按照下面的步骤来执行本 skill：

1. **确认文件路径**：从用户的话语中提取出用户想要分析的日志文件路径。
   如果用户没有明确说出路径，就询问用户日志文件在哪里。

2. **运行分析脚本**：使用下面的命令来运行本 skill 提供的分析脚本，把日志文件
   路径作为第一个参数传进去：

   ```bash
   python skill-v1-未优化/log-stats/scripts/analyze.py <日志文件路径>
   ```

   如果想要控制"最多错误"列表显示的条数，可以传入第二个参数（默认是 5 条）：

   ```bash
   python skill-v1-未优化/log-stats/scripts/analyze.py <日志文件路径> 10
   ```

3. **展示报告**：脚本会把统计报告直接打印到标准输出，把这份报告完整地展示给用户。

4. **补充解读**：在报告的基础上，用一两句话帮用户总结日志的关键情况，比如
   错误是不是特别多、哪个时间段是高峰、有没有值得注意的异常。

## 报告包含的内容

脚本生成的报告会包含以下几个部分：

- **总行数**：日志文件一共有多少行。
- **各级别统计**：DEBUG、INFO、WARN、ERROR 各自有多少条，以及各自占总数的百分比。
- **Top N 错误**：出现次数最多的若干条 ERROR 级别日志内容，以及每条出现的次数。
- **每小时请求量**：按小时（00~23）统计每个小时出现了多少条日志，用来看流量高峰。

## 报告输出格式示例

脚本打印出来的报告大概是下面这个样子的，供参考：

```
========== 日志统计报告 ==========
文件：app.log
总行数：120000

--- 各级别统计 ---
DEBUG :  40012  (33.3%)
INFO  :  60005  (50.0%)
WARN  :  15003  (12.5%)
ERROR :   4980  ( 4.2%)

--- Top 5 错误 ---
 1. [ 1203 次] Database connection timeout after 30s
 2. [  890 次] Failed to parse request body
 3. [  654 次] Redis connection refused
 4. [  432 次] Null pointer in handler
 5. [  321 次] Rate limit exceeded for ip=...

--- 每小时请求量 ---
00 时: 3200
01 时: 2980
...
23 时: 5010
==================================
```

## 注意事项

- 如果某一行不符合上面说的日志格式（比如是一行堆栈跟踪、空行、或者格式错乱的行），
  脚本会把它当作"无法解析"的行跳过，不计入级别统计，但仍然计入总行数。
- 日志级别的匹配是大小写敏感的，只识别大写的 DEBUG、INFO、WARN、ERROR。
- Top N 错误统计的是 ERROR 级别日志的"内容"部分完全相同的行，把它们归并计数。
- 每小时请求量是根据每行开头时间戳里的小时字段（HH）来归类的。
- 如果日志文件非常大（比如几百 MB 甚至上 GB），脚本可能会比较慢或占用较多内存，
  这属于已知情况，耐心等待即可。
