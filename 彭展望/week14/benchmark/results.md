# Benchmark 实测结果

测试环境：macOS，Python 3.13.9，测试日志 `test.log`（200 万行，约 105 MB，固定随机种子 42 可复现）。
复现命令：

```bash
python gen_log.py test.log 2000000      # 生成测试日志
python benchmark.py test.log 3          # 执行效率对比（每版本跑 3 次取最优）
python count_tokens.py                  # SKILL.md token 消耗对比
```

## 一、执行效率（脚本优化）

```
测试文件：test.log（105.4 MB）  每版本跑 3 次取最优

=== 结果一致性校验 ===
两个版本输出完全一致：是 ✅

=== 执行效率对比 ===
版本           耗时(s)        峰值内存
v1 未优化       3.047        249.4 MB
v2 优化后       1.316        11.4 MB

速度提升：2.32x
内存下降：21.89x
```

- **速度 2.32x**：v1 对文件做了 3 趟遍历、且正则在循环内反复编译；v2 单趟流式遍历 + 正则预编译。
- **内存 21.89x**：v1 用 `readlines()` 把整个文件读进内存（249 MB）；v2 逐行流式处理，内存与文件大小无关（11 MB，基本是解释器底噪）。
- **正确性**：两版输出逐字节一致，优化未改变结果。

## 二、Token 消耗（SKILL.md 优化）

```
文件                           tokens     字符数
v1 SKILL.md                  1860       2748
v2 SKILL.md（常态加载）            362        607
v2 reference.md（按需）          447        809

每次触发 skill 的常态 token： v1=1860 → v2=362，降幅 80.5%（省 1498 tokens）
即使 v2 需加载 reference.md，总量 809 tokens，仍比 v1 少 56.5%
```

- v1 把格式说明、触发例句、报告样例、注意事项全部内联，每次触发都全量进上下文。
- v2 用**渐进式披露**：SKILL.md 只留触发描述 + 3 步流程，冗长细节挪到 `reference.md`，仅在需要核对格式时才加载。
