## 1. Yi 系列(01-AI):Llama 改良 → MoE 旗舰

### 1.1 Yi-1.5 系列(dense,Llama 系改良)

Yi-1.5 在 LlamaForCausalLM 基础上做参数调整,代表规格 Yi-1.5-9B-32K:

| 维度 | 数值 | 说明 |
|---|---|---|
| 架构类 | LlamaForCausalLM | 直接复用 Llama 生态工具链 |
| 参数量 | 8.83B(9B) / 34.4B(34B) | dense,无 MoE |
| 层数 / hidden | 48 / 4096(9B);54 / 7168(34B) | 标准 Transformer |
| 注意力 | **GQA**:32 Q 头 / 4 KV 头(head_dim 128) | 在显存与质量间平衡 |
| FFN | SwiGLU,intermediate 11008 | 与 Llama 2 一致 |
| 归一化 | RMSNorm 1e-6 + Pre-Norm | |
| 位置编码 | **RoPE theta = 5e6**(Llama 默认 1e4) | 显著拉高,是 32K 上下文的关键 |
| 上下文 | 4K 原生 → **32K**(Yi-1.5-9B-32K 变体) | 通过 rope_theta 扩展,无 YaRN |
| 词表 | 64,000 | 数字拆字 + 代码空格 token |
| 精度 | bf16 | |

**特点**:Yi-1.5 几乎是"调过 rope_theta 的 Llama 2",没有引入 Gated DeltaNet、MLA 等新机制;靠数据与 rope_theta 把 9B 模型推到 32K 上下文。

### 1.2 Yi-Lightning(MoE 旗舰,2024-10)

| 维度 | 数值 / 机制 | 说明 |
|---|---|---|
| 架构类 | enhanced MoE | 总参 **200B**,训练 10T tokens |
| MoE 路由 | **细粒度专家分段** + 组级负载均衡 + aux loss | 把每个专家 FFN 切成更小单元,多专家同 token 并行 |
| **KV Cache 优化** | **混合注意力**:局部滑窗 + 全注意力交替,跨层共享 KV | 内存降 **82.8%**,长上下文关键 |
| 上下文 | 64K(通过 RoPE scaling 扩展) | |
| 训练范式 | 三阶段:初始预训练 → mid-training → fast-decay 高质量上采样 | |
| 安全 | **RAISE** 框架:4 组件覆盖 pre/post/serving | |
| 性能 | Chatbot Arena 第 6,中文/数学/代码/Hard Prompts 第 2-4 | 2024-10 旗舰 |

**特点**:Yi-Lightning 是 Yi 系列唯一走 MoE 路线的版本,核心创新是**混合注意力降 KV cache**——这与 Qwen3.8 的"线性注意力降 KV"是不同路线,但目标一致。

### 1.3 与 Qwen3.8 对照

- Yi-1.5 与 Qwen3 系前代同属 Llama 改良,但 Yi 未跟进 Gated DeltaNet;
- Yi-Lightning 的"滑窗 + 全注意力混合"近似 Qwen3.8 的"线性 + 全注意力混合"思路,但用的是传统稀疏注意力而非线性注意力;
- Yi 未启用 MTP。

## 2. Baichuan 系列(百川):Llama 改良 + 多模态

### 2.1 Baichuan 2(7B / 13B,2023-09)

| 维度 | 数值 / 机制 | 说明 |
|---|---|---|
| 架构类 | BaichuanForCausalLM(Llama 系变体) | |
| 参数量 | 7B / 13B,2.6T tokens | 当时开源最大训练量 |
| 词表 | **BPE 12 万** | 不做归一化、数字拆字、为代码加空格 token,覆盖率 0.9999 |
| FFN | **SwiGLU**(hidden 缩到 8/3 再对齐 128 倍数) | Llama 2 同款 |
| 归一化 | **Pre-Norm + RMSNorm**(Transformer 输入加 LayerNorm 利于 warmup) | 双 norm 策略 |
| 位置编码 | **7B 用 RoPE** + Flash Attention;**13B 用 ALiBi** + xFormers | 同系列内部分化 |
| 稳定性 | **NormHead**(对输出 embedding 做 L2 归一化)+ **Max-z loss**(拉低 logits) | 解决训练后期 logits 爆炸 |
| 精度 | bf16(位置编码 / 优化器用全精度) | |

**特点**:Baichuan 2 的"7B 用 RoPE、13B 用 ALiBi"是少见的同系列内分叉;NormHead + Max-z loss 是其训练稳定性独家 trick。

### 2.2 Baichuan-Omni(7B 多模态,2024-10)

| 维度 | 数值 / 机制 | 说明 |
|---|---|---|
| 架构类 | Baichuan 7B LLM 底座 + 多模态投影 | |
| 视觉编码器 | **SigLIP-384px**(384×384 输入) | 不同于 Qwen3.8 的自研 ViT |
| 视觉投影 | 2 层 MLP + 2×2 卷积 pooling → 182 tokens | AnyRes 切块策略 |
| 模态 | 图像 + 视频 + 音频 + 文本(omni) | 国内较早开源 omni-MLLM |
| 交互 | 流式输入:预测音频起止 → 视频流式注入 → 音频特征推理 | |

**特点**:Baichuan-Omni 走 SigLIP + AnyRes 路线,与 Qwen3.8-27B 的"自研 ViT + spatial merge"是两条多模态集成路径。

## 3. MiniCPM 系列(OpenBMB):端侧高效 + 稀疏注意力

### 3.1 演进路线

| 版本 | 发布 | 参数 | 关键创新 |
|---|---|---|---|
| MiniCPM-1B/2B | 2024-02/04 | 1B/2B | dense,性能比肩 Mistral-7B |
| MiniCPM-S-1B | 2024-07 | 1B | FFN 稀疏度 87.89%,FFN FLOPs 降 84% |
| MiniCPM-MoE-8x2B | 2024-04 | 2B×8 | MoE 化尝试 |
| MiniCPM3-4B | 2024-09 | 4B | **MLA 注意力**(类 DeepSeek),比肩 Llama3.1-8B |
| **MiniCPM4** | 2025-06 | 0.5B / 8B | **InfLLM v2 可训练稀疏注意力** |
| MiniCPM4.1 | 2025-09 | 0.5B/8B | 混合推理模型(深度推理 + 非推理双模式) |
| **MiniCPM-SALA** | 2026-02 | 9B | 稀疏 + 线性混合注意力,1M 上下文 |

### 3.2 MiniCPM3-4B(MLA 路线)

- 4B 参数,首度在国产端侧模型采用 **MLA(Multi-head Latent Attention)**,与 DeepSeek-V3 同源;
- 通过 MLA 压缩 KV cache,使 4B 模型能在端侧跑长上下文;
- 性能超越 Phi-3.5-mini、GPT-3.5-Turbo,比肩 Llama3.1-8B / Qwen2-7B / GLM-4-9B-Chat。

### 3.3 MiniCPM4(InfLLM v2 稀疏注意力,2025-06)

| 维度 | 数值 / 机制 | 说明 |
|---|---|---|
| 架构类 | MiniCPM4ForCausalLM | 0.5B / 8B 两档,8B 训练 8T tokens |
| **注意力** | **InfLLM v2**:可训练稀疏注意力 | 128K 时每 token 仅与 **<5% token** 计算相关性 |
| 训练算法 | **Model Wind Tunnel 2.0**:scaling 预测,精准超参搜索 | |
| 量化 | **BitCPM**:三值量化,位宽降 90% | 0.5B / 1B 版本 |
| 训练精度 | FP8 + **MTP**(多 token 预测) | |
| 数据 | **UltraClean** + **UltraChat v2**(开源 Ultra-FineWeb) | |
| 推理 | **CPM.cu**:轻量 CUDA 框架 + 稀疏注意力 + 量化 + 投机采样 | 端侧 5× 加速 |
| 投机 | Eagle head(FRSpec / vLLM / QAT-cpmmu 多版本) | |

### 3.4 MiniCPM-SALA(2026-02,最新)

- **首个大规模稀疏 + 线性混合注意力开源模型**;
- 9B 规模,1M token 上下文;
- OpenBMB + SGLang + NVIDIA 合作,2026 SOAR 大赛基准(单卡 NVIDIA 6000D 上 9B/1M 推理优化)。

### 3.5 与 Qwen3.8 对照

MiniCPM 与 Qwen3.8 是**最直接的对照点**:
- 两者都用"混合注意力"解决长上下文:Qwen3.8 = 线性(Gated DeltaNet)+ 全注意力;MiniCPM-SALA = 稀疏(InfLLM v2)+ 线性;
- 规模正交:Qwen3.8 旗舰 2.4T,MiniCPM 旗舰 8B(端侧定位);
- MiniCPM 的稀疏度更激进(InfLLM v2 仅 5% token 参与注意力),但 Qwen3.8 的线性注意力是 O(n) 复杂度,理论上更优;
- 都启用 MTP。

## 4. InternLM 系列(上海 AI Lab):工具调用 + 1M 上下文

### 4.1 InternLM 2.5(dense,2024-07)

| 维度 | 数值 / 机制 | 说明 |
|---|---|---|
| 架构类 | InternLM2ForCausalLM | dense,无 MoE |
| 参数量 | 7B / 20B | 7B 用得最多 |
| 层数 / hidden | 32 / 4096(7B) | |
| 注意力 | **GQA**:32 Q 头 / 8 KV 头,head_dim 128 | |
| 词表 | 92,544 | 中英多语兼顾 |
| 上下文 | **1,048,576**(1M,InternLM2.5-7B-Chat-1M 变体) | rope_scaling_factor=2.5 + max_position=262144 扩展 |
| 工具调用 | 强调"上百个网页搜集 + 工具筛选 + 结果反思" | 智能体导向 |
| 推理 | LMDeploy 官方推荐(rope_scaling_factor + session_len 配置) | |

### 4.2 InternLM 3(8B,2025)

- 8B dense,FFN intermediate 10240;
- 配套 InternViT 形成 InternVL3 多模态系列(ViT-MLP-LLM 范式);
- 引入 **V2PE(Variable Visual Position Encoding)**:对视觉 token 用更小更灵活的位置增量,提升长上下文多模态能力;
- **原生多模态预训练**:语言与视觉数据交织在单一预训练阶段,不先训纯文本再对齐。

### 4.3 与 Qwen3.8 对照

- InternLM 2.5/3 走 dense + GQA + RoPE scaling 的"保守"路线,与 Qwen3.8 的混合线性注意力路线截然不同;
- 1M 上下文方案:InternLM 靠 RoPE scaling,Qwen3.8 靠线性注意力降复杂度,DeepSeek-V4 靠稀疏 + KV 压缩;
- InternLM 强调工具调用与智能体能力,这是 Qwen3.8 文档中未强调的卖点;
- 未启用 MTP(文档未声明)。

## 6. 四大技术路线归纳(扩展)

在 [qwen38_架构对比.md](./qwen38_架构对比.md) 第 4 节归纳的 4 条技术路线基础上,可补充:

5. **Llama 系改良 + GQA + RoPE scaling 流(Yi-1.5 / Baichuan 2 / InternLM 2.5)**:结构最保守,靠 rope_theta 拉升 / scaling factor 撑长上下文,无 MLA / 线性 / 稀疏注意力。Baichuan 2 在此基础上加 NormHead / Max-z loss 提升训练稳定性。

6. **端侧稀疏 + 线性混合流(MiniCPM)**:InfLLM v2 可训练稀疏注意力(<5% token 参与)+ 线性注意力,9B 规模实现 1M 上下文;辅以 BitCPM 三值量化、Model Wind Tunnel 2.0 scaling law、CPM.cu CUDA 框架,系统级协同。

**新增共性**:
- ⑦ **NormHead / Max-z loss** 等训练稳定性 trick(Baichuan 2)在 Llama 系改良路线中常见;
- ⑧ **RoPE scaling(2.5× 等)** 是 dense 模型实现 1M 上下文的最简方案(InternLM 2.5);
- ⑨ **端侧稀疏化** 已成端侧模型标配(MiniCPM InfLLM v2 / MiniCPM-S FFN 稀疏 87.89%);
- ⑩ **三值量化(BitCPM)** 是比 FP4 更激进的端侧部署路径,位宽降 90%。

## 7. 关键结论

1. **Yi 系"两条腿"**:Yi-1.5 是 Llama 系改良(rope_theta 拉到 5e6 是 32K 关键),Yi-Lightning 是 MoE 旗舰(细粒度专家分段 + 滑窗/全注意力混合降 KV 82.8%);后者与 Qwen3.8 的"混合注意力"思路异曲同工,但用的是传统稀疏而非线性注意力。

2. **Baichuan 2 的独家 trick**:**NormHead**(输出 embedding L2 归一化)+ **Max-z loss**(拉低 logits)是其训练稳定性的核心;7B/13B 内部 RoPE/ALiBi 分叉是少见的设计选择。Baichuan-Omni 用 SigLIP + AnyRes 走 omni-MLLM 路线。

3. **MiniCPM 是国产"线性 + 稀疏混合注意力"的端侧代表**:从 MiniCPM3 的 MLA 路线,演进到 MiniCPM4 的 InfLLM v2 稀疏(<5% token 参与),再到 2026-02 的 SALA(稀疏 + 线性混合,1M 上下文)——这是与 Qwen3.8 Gated DeltaNet 路线**最直接竞争**的国产方案,但规模正交(9B vs 2.4T)。

4. **InternLM 2.5/3 走"保守 dense + 工具调用"路线**:GQA + RoPE scaling 2.5× 实现 1M 上下文,结构上无 MLA/稀疏/线性创新,靠 1M 上下文 + 工具调用 + 智能体能力差异化竞争;InternLM 3 + V2PE 把多模态做原生预训练。

5. **四系列与 Qwen3.8 的关系**:
   - 结构最接近的是 **MiniCPM-SALA**(都是混合注意力 + MTP,但稀疏 vs 线性路线不同);
   - 路线最远的是 **InternLM 2.5**(纯 GQA dense,无任何注意力创新);
   - Yi-Lightning 与 Qwen3.8 都是"混合注意力降 KV cache",但 Yi 用传统稀疏 + 跨层共享,Qwen3.8 用线性注意力;
   - Baichuan 2 与 Qwen3 前代同为 Llama 改良,但 Baichuan 未跟进后续 MLA/线性注意力演进。
