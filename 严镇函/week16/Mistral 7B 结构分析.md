# Mistral 7B 结构分析

论文[Mistral 7B | 论文 | HyperAI超神经](https://hyper.ai/cn/papers/2310.06825) ） 

## 2.1 模型简介

Mistral 7B 是一个拥有 70 亿参数的大语言模型，主要有两个注意力机制改进：**分组查询注意力（GQA）** 与 **滑动窗口注意力（SWA）**，在保证模型质量的同时，大幅提升了推理速度与显存效率。

## 2.2 整体架构

模型基于标准 Transformer 解码器架构，核心结构参数如下：

- **隐藏层维度**：4096
- **网络层数**：32
- **注意力头维度**：128
- **前馈网络维度**：14336
- **查询头（Q）数量**：32
- **键值头（KV）数量**：8（分组查询注意力配置）
- **滑动窗口大小**：4096

## 2.3 分组查询注意力（GQA）

### 核心思想

原来 **MHA 模式** 是一个 Q 对应一个 K 和 V，会导致 KV 缓存占用很大。

Q1 → 自己的 K/V  
Q2 → 自己的 K/V  
Q3 → 自己的 K/V  
Q4 → 自己的 K/V  

**GQA 模式** 将多个 Q 分为一组，同组内的 Q 共用一组 K/V：

Q1 ─┐  
Q2 ─┤  
Q3 ─┤ → 共用 K/V  
Q4 ─┘  

这样减少了 KV Cache，推理更省资源。

### 具体配置

Mistral 7B 采用 **GQA-4** 方案（32 个 Q 头，8 个 KV 头，分组数为 4），在多头注意力和多查询注意力（MQA）之间取得了良好平衡。

## 2.4 滑动窗口注意力（Sliding Window Attention, SWA）

### 核心思想

之前 Transformer 中每个 token 可以关注之前的所有 token。SWA 将每个 token 的注意力限制在**前一层中距离不超过 W 个位置的 token** 范围内（例如 W=3 则只能看到前三个 token 的内容）。

### 跨层信息传递与理论感受野

由于多层堆叠，信息可以逐渐传播。

Mistral 7B 的窗口大小 W = 4096，共 32 层，因此**理论注意力跨度可达 4096 × 32 ≈ 131,000 个 token**。

### 滚动缓存机制

由于注意力跨度固定，Mistral 使用**滚动缓冲区**来存储 KV 缓存：

- 缓存大小固定为 W
- 时间步 i 的键/值存储在位置 **i mod W**
- 当 i > W 时，旧值被新值覆盖，缓存大小不再增长

对于 32,000 token 的序列，这种方法可将缓存内存使用量**减少 8 倍**。

## 2.5 设计动机

| 挑战             | GQA 的解决方案                  | SWA 的解决方案                   |
| :--------------- | :------------------------------ | :------------------------------- |
| KV 缓存占用过大  | 多查询头共享 KV，缓存缩减为 1/4 | 滚动缓存，内存不再随序列线性增长 |
| 长序列计算成本高 | —                               | 复杂度从 O(n²) 降至 O(n × W)     |
| 推理延迟高       | 减少内存加载，加速解码          | 固定注意力跨度，提升吞吐量       |
| 批处理规模受限   | 内存释放支持更大 batch          | 缓存可控，支持更大 batch         |

## 2.6 优势与局限

### 优势

| 方面           | 说明                                       |
| :------------- | :----------------------------------------- |
| **推理速度**   | GQA 显著加速推理，SWA 降低计算复杂度       |
| **内存效率**   | KV 缓存减少 75%，滚动缓存减少 8 倍内存使用 |
| **长序列处理** | 理论注意力跨度达 131K token                |
| **高性能**     | 在推理、数学、代码生成上超越 Llama 2 13B   |
| **开源**       | Apache 2.0 许可证发布                      |

### 局限

| 方面             | 说明                                                         |
| :--------------- | :----------------------------------------------------------- |
| **窗口限制**     | 单层内每个 token 只能看到 W 个 token，依赖跨层传递获取全局信息 |
| **理论 vs 实际** | 131K 的理论跨度需要 32 层逐层传递，实际效果受层数限制        |
| **非窗口内信息** | 超出窗口的信息需要通过多层间接传递，可能存在信息衰减         |
| **预填充限制**   | 长提示需要分块处理，增加了预处理复杂度                       |
