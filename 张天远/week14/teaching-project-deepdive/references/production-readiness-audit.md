# 生产级可落地性审计框架

> 教案写完后，从"真实案例参考"维度诊断缺口。与"交付前自检清单"互补——自检清单看教学结构，审计清单看工程真实感。

## 触发条件

- 用户问"这个项目能落地吗？"、"差距在哪里？"
- 教案覆盖了完整链路但用户要求评估"工程可信度"
- 项目是 ML/LLM 系统且涉及 API 调用、向量库、用户交互等

## 六个常见信息缺口

按优先级排序：

| # | 缺口 | 诊断问题 | 本会话 RAG 教案示例 |
|---|------|---------|-------------------|
| 1 | 成本模型 | 建索引花多少？每次问答花多少？规模化后翻几倍？ | 补了 API 费/本地 BGE/三档策略表 |
| 2 | 选型决策框架 | 为什么选 DashScope 不选自建？什么场景换什么？ | 补了决策树 + 三场景三配置 |
| 3 | 失败模式展示 | 系统运行中真实翻车案例，不只是开发期的 bug | 补了"有引用的幻觉"+"检索噪声"两案例 |
| 4 | Prompt 迭代历史 | 最终 Prompt 是怎么到达的？不是一次写对的 | 补了 v1→v4 四版迭代 |
| 5 | 增量更新策略 | 新增数据怎么处理？全量重建还是增量？ | 补了多索引并行策略 |
| 6 | 安全考量 | 用户输入含注入攻击怎么办？检索文档含隐藏指令呢？ | 补了四层防御（输入/Prompt/沙箱/输出） |

## 两个常见逻辑断层

| # | 断层 | 症状 | 修复 |
|---|------|------|------|
| 1 | 选型缺乏量化数据 | "语义分块更好"但没有 Hit Rate 数字 | 补消融实验对比表（可以是预期范围） |
| 2 | 评估指标缺乏因果链 | 分别介绍 Faithfulness/Context Precision，但不讲它们的因果关系 | 补诊断流程图——哪个指标低优先修哪里 |

## 七个生产级差距（ML/RAG 项目通用）

按致命程度排序：

| # | 差距 | 严重度 | 适用范围 |
|---|------|--------|---------|
| 1 | 幻觉控制无闭环 | 🔴 致命 | 所有 RAG 系统 |
| 2 | 不能聚合/多跳推理 | 🔴 致命 | 需要跨文档综合的系统 |
| 3 | 无多轮对话 | 🟡 重要 | 对话式交互场景 |
| 4 | 数据源单一 | 🟡 重要 | 多格式/多频次数据场景 |
| 5 | 无缓存降级 | 🟡 重要 | 依赖外部 API 的系统 |
| 6 | 安全防护为零 | 🟠 中等 | 暴露给用户的系统 |
| 7 | 无增量更新 | 🟢 可接受 | 数据持续增长的系统 |

## 执行方式

1. 教案初稿完成后，主动跑一轮此审计
2. 把发现的缺口和断层分类：高优（补入正文）、中优（补入附录）、低优（提及即可）
3. 用户问"这个能落地吗"时，直接出示此框架的分析结果
4. 更新教案时，用 `execute_code` + Python 批量插入（避免行号漂移）——参见 SKILL.md 常见错误表中"ctx_edit 大段中文回退方案"
