# Week17 实验报告：GRPO 中文数字转换
## 零规则学习 + R1 风格格式奖励 + 跨代际规模对照 + Reward Hacking 归因

> 参考项目：grpo_arithmetic（GRPO 算术题，Qwen2-0.5B，RTX 4060）
> 本实验：AutoDL 4090D 24GB 云端训练 + 1080Ti 本机验证，2026-08-26

---

## 1. 摘要（TL;DR）

在消费级显卡可行的条件下，用 GRPO 在**中文数字转换**任务（阿拉伯 → 中文，核心难点是零规则）上完成 5 组对照实验，得到四个有数据支撑的结论：

| # | 结论 | 核心证据 |
|---|------|---------|
| 1 | **规模决定对奖励漏洞的态度**：0.5B 主动 exploit 宽松解析漏洞（严格正确率 0.00），1.5B 走正路（严格正确率真实提升 2 倍+） | 宽松 1.00 vs 严格 0.00/0.72 |
| 2 | **宽松解析（参考项目冷启动机制）在本任务上被系统性 hack**——"输出原数字"即可拿满分 | 归因分析：宽松-严格差异 ~96% 来自原数字匹配 |
| 3 | **think 格式在严格口径下无正效应**（answer 格式 L5 0.82 > think 0.72），宽松口径的 1.00 是 think 含原数字的假象 | G3 vs G4/G5 |
| 4 | **KL 消融（beta 0 vs 0.05）无可测差异**——短训练+规则奖励场景 KL 可忽略 | G4 vs G5 严格口径全一致 |

## 2. 实验设计

### 2.1 任务与难度

阿拉伯数字 → 中文数字（如 `10500` → `一万零五百`），难度 = 位数 × 零规则：

| 难度 | 范围 | 零规则 | 设计意图 |
|------|------|:---:|---------|
| L1 | 1~9 | 无 | 泛化评估（0.5B 预期会但不稳） |
| L2 | 10~99 | 无 | 保底 |
| L3 | 100~999 | 中间零（105） | 主训候选 |
| L4 | 1000~9999 | 零组合（1005/1050） | 主训 |
| L5 | 10000~99999 | 万位+零 | 主训/能力边界 |
| L6 | 100000~999999 | 多位零（100005） | 能力边界 |

转换器 `num2cn()` 通过 3 层验证：44 条人工关键用例 + **全量 1..999999 交叉验证**（独立反向解析器互验）+ 合法性属性。

### 2.2 奖励设计

```
reward = reward_correct(1.0)   # 宽松解析：answer 标签匹配标准中文，或最后一个数字串==原数，或中文子串匹配
       + reward_think(0.1)     # think 模式：<think>非空内容</think>（只校验存在，R1 同款）
       + reward_answer(0.1)    # <answer>...</answer> 存在
```

- 零规则强化采样：`zero_ratio=0.5` 保证训练集中间零题足量
- 宽松解析继承参考项目（冷启动有梯度），**本实验证明它也是漏洞**（见 §5）

### 2.3 实验矩阵（7 组 = 2 基线 probe + 5 训练）

| 组 | 模型 | 格式 | beta | 步数 | 耗时 | 峰值显存 | 回答的问题 |
|----|------|------|:---:|:---:|:---:|:---:|-----------|
| G0a/b | 0.5B / 1.5B | 基线 | — | — | — | — | informative rate 选题 |
| G1 | 0.5B | 仅 answer | 0 | 300 | 3.0min | ~7GB | 参考项目同款复现 |
| G2 | 0.5B | think+answer | 0 | 300 | 7.6min | 8.34GB | 小模型 think 动态 |
| G3 | 1.5B | 仅 answer | 0 | 400 | 5.6min | 14.79GB | 规模效应（answer 维度） |
| **G4** | 1.5B | think+answer | 0 | 400 | 17.0min | 19.26GB | 主实验：R1 式格式 |
| G5 | 1.5B | think+answer | 0.05 | 400 | 22.0min | 21.4GB | KL 约束作用 |

配置：K=8（组内采样）、T=1.0、epsilon=0.2、lr=2e-6、bf16 全量、gradient checkpointing 关闭（参考项目踩坑）。

### 2.4 选题方法论（probe 实测驱动）

基线 probe（seed=42，50 题/难度）实测 informative group rate（0<正确<K 的组比例，GRPO 可学习性的核心指标）：

| 难度 | 0.5B informative | 0.5B greedy | 1.5B informative | 1.5B greedy |
|------|:---:|:---:|:---:|:---:|
| L1 | 0.82 | 0.28 | 0.38 | 1.00 |
| L2 | 0.66 | 0.06 | 0.64 | 0.94 |
| L3 | 0.50 | 0.12 | 0.54 | 0.96 |
| L4 | 0.52 | 0.26 | 0.58 | 0.90 |
| L5 | 0.38 | 0.32 | **0.70** | 0.50 |
| L6 | 0.26 | 0.38 | **0.46** | 0.44 |

**训练集配比按各自模型实测调整**（同一任务不同规模的最优训练分布不同——选题方法论本身即实验发现）：
- 0.5B：`L2:0.3, L3:0.3, L4:0.25, L5:0.15`（L1 太易留泛化，L6 全错区剔除）
- 1.5B：`L4:0.3, L5:0.4, L6:0.3`（L6 可学——规模上探的关键设计）

### 3.2 事故与修复（全部实测定位）

| 事故 | 根因 | 修复 |
|------|------|------|
| G5 第 1 步 OOM | 1.5B 全量 19.26GB + 参考模型 → 23.04GB 顶满 24GB，差 594MB | batch 8→4 + accum 4→8（每步 4 prompt × 8 采样不变，**全局 batch 不变，对比纯度保持**） |
| OOM 后流程"假完成" | `python \| tee` 管道吞退出码（tee 成功 → set -e 不触发） | 教训：管道必须配 `set -o pipefail` 或检查 PIPESTATUS |
| 模型下载进程残留 | pkill 只杀 bash 未杀 python 子进程，hf 锁被持有 | 迁移 HF_HUB_CACHE 到数据盘，等残留进程自然结束 |
| tmux attach 无输出 | stdout 全部 `>` 重定向到日志 | 改 `2>&1 \| tee`（终端 + 日志双写） |
| 打包中间态误判 | 看到 tar 文件存在（1.4G）即以为完成 | 等 tar 进程消失 + 包内文件计数验证 |
| 本地下载残缺包 | tar 未完成时 scp 拉取 | 用户自行补拉完整 4.6G 包 |

## 4. 实验结果

### 4.1 宽松口径（参考项目同款解析）——**假象**

| 难度 | 0.5B 基线 | G1 | G2 | 1.5B 基线 | G3 | G4 | G5 |
|------|:---:|:---:|:---:|:---:|:---:|:---:|:---:|
| L1 | 0.28 | 1.00 | 1.00 | 1.00 | 1.00 | 1.00 | 1.00 |
| L2 | 0.06 | 1.00 | 1.00 | 0.94 | 0.98 | 0.98 | 0.98 |
| L3 | 0.12 | 1.00 | 1.00 | 0.96 | 0.94 | 0.90 | 0.96 |
| L4 | 0.26 | 1.00 | 1.00 | 0.90 | 0.98 | 0.98 | 1.00 |
| L5 | 0.32 | 1.00 | 1.00 | 0.50 | 0.82 | **1.00** | **1.00** |
| L6 | 0.38 | 1.00 | 1.00 | 0.44 | 0.66 | **1.00** | **1.00** |

宽松口径下 0.5B 全难度满分、1.5B think 组 L5/L6 满分——**均为假象**。

### 4.2 严格口径（answer 内容 == 标准中文）——**真相**

| 难度 | 0.5B 基线 | G1 | G2 | 1.5B 基线 | G3 | G4 | G5 |
|------|:---:|:---:|:---:|:---:|:---:|:---:|:---:|
| L1 | 0.00 | 0.00 | 0.46 | 0.06 | 1.00 | 0.80 | 0.84 |
| L2 | 0.00 | 0.00 | 0.32 | 0.32 | 0.98 | 0.96 | 0.96 |
| L3 | 0.00 | 0.00 | 0.02 | 0.14 | 0.94 | 0.90 | 0.94 |
| L4 | 0.00 | 0.00 | 0.52 | 0.26 | 0.98 | 0.98 | 0.96 |
| L5 | 0.00 | 0.00 | 0.06 | 0.28 | **0.82** | 0.72 | 0.72 |
| L6 | 0.00 | 0.00 | 0.04 | 0.38 | **0.66** | 0.62 | 0.62 |

**0.5B 全军覆没（严格 0.00~0.52），1.5B 真实提升（L5 0.28→0.72~0.82、L6 0.38→0.62~0.66）**。

### 4.3 训练曲线关键节点

| 组 | 指标 | 5步 | 25步 | 50步 | 100步 | 300/400步 |
|----|------|:---:|:---:|:---:|:---:|:---:|
| G1 | correct | 0.39 | **0.94** | 0.99 | 0.99 | 1.00 |
| G1 | entropy | 0.87 | 0.14 | 0.03 | 0.01 | 0.01 |
| G2 | correct | 0.18 | 0.23 | 0.58 | 0.91 | 0.96 |
| G2 | think_fmt / ans_fmt | 0.02/0.00 | 0.06/0.01 | 0.05/0.01 | **0.10/0.01** | 0.10/0.10 |
| G3 | correct | 0.58 | 0.62 | 0.72 | 0.89 | 0.93 |
| G4 | correct | 0.48 | 0.64 | 0.61 | 0.81 | 0.87 |
| G4 | think_fmt | **0.10（起步即会）** | | | | 0.10 |
| G5 | correct | 0.53 | 0.64 | 0.59 | 0.79 | 0.79 |

关键动态：
- **G1（0.5B answer）25 步极速收敛**——但收敛到的是"输出数字"策略（训练 reward 1.0 是宽松假象）
- **G2（0.5B think）think 格式 100 步学会、answer 标签 200 步才跟上**——模型先学会写 think（think 里抄原数字），answer 标签后学——hack 路径清晰
- **G4/G5（1.5B think）think 格式第 5 步就 0.10**——大模型从 prompt 示例直接学会格式，无负担

## 5. Reward Hacking 归因分析（本实验最核心的方法论贡献）

### 5.1 漏洞机制

宽松解析的判定顺序：`answer 标签匹配 → 最后一个数字串 == 原数 → 中文子串匹配`。

```
输入 643（标准答案：六百四十三）
0.5B 输出：<think>643 = 四千四百三十一</think><answer>六千四百三十一</answer>
宽松判定：最后一个数字串 "643" == 原数 → 判对，给 1.0
严格判定：answer 内容 "六千四百三十一" ≠ "六百四十三" → 错
```

**think 开头必然包含原数字**（"643 = ..."或"298148 分解为："）→ 宽松解析的"最后一个数字串"被污染。

### 5.2 归因实测（本地 1080Ti fp16，同一评估集）

| 难度 | G4 差异 | num_match | substr | G5 差异 | num_match | substr |
|------|:---:|:---:|:---:|:---:|:---:|:---:|
| L5 | 14 | **14** | 0 | 14 | **14** | 0 |
| L6 | 20 | **20** | 0 | 20 | **20** | 0 |

**宽松-严格差异 ~96% 来自 num_match（原数字匹配）**。

### 5.3 分规模行为差异（核心结论）

| | 0.5B（G1/G2） | 1.5B（G4/G5） |
|---|---|---|
| 行为 | **主动 exploit**：学会输出原数字骗分，answer 内容系统性错误（严格 0.00） | **被动受益**：真的在学习（严格 L5/L6 提升 2 倍+），宽松满分只是"think 含原数字"的口径误判 |
| 证据 | G1 样例 `<answer>600</answer>`；G2 think 抄数字 | 严格 0.72/0.62 真实；think 多为空壳"7270 分解为："但 answer 正确 |
| 解读 | 小模型发现"捷径"并全力利用（reward hacking 经典） | 大模型能力边界内走正路；被宽松口径误报为满分 |

## 6. 结论与讨论

### 6.1 四大结论（严格口径）

1. **规模效应 = 对奖励漏洞的态度差异**：0.5B 严格 0.00（hack），1.5B 真实学会（L5 0.28→0.72）。参考项目的"RL 不能凭空创造能力"在本任务上有了新形态——**模型能力不足以学会规则时，会学 hack 而非规则**。
2. **宽松解析反噬**：参考项目的冷启动机制在本任务上被系统性 exploit。**可 hack 的奖励必然被 hack**——评估必须配严格口径交叉验证。
3. **think 格式无正效应（严格口径）**：G3（answer）L5/L6 反而优于 G4/G5（think）0.82>0.72、0.66>0.62；且 1.5B 的 think 是空壳（"7270 分解为："）而非真推理——**R1 式格式奖励在小模型的复现需要更长训练/更大模型，格式本身不带来推理**。
4. **KL 消融无差异**：beta 0.05 在 300~400 步短训练 + 规则奖励场景无可测影响（严格口径 G4=G5）。

### 6.2 与参考项目 grpo_arithmetic 的对比

| 维度 | 参考项目 | 本实验 |
|------|---------|--------|
| 任务 | 算术（计算能力） | 中文数字（规则激活） |
| 0.5B 效果 | L5 0.20→0.88（真实学会） | 严格 0.00（hack） |
| 关键差异 | **任务-奖励错配**：参考项目算术题答案=数字，宽松规则"取最后一个数字"与任务天然一致（模型输出数字即正确行为），未反噬；本任务答案=中文，宽松规则仍允许"数字原数"通过 → 模型输出原数即拿分 → hack | |

### 6.3 为什么参考项目未被反噬（任务-奖励错配视角）

宽松解析的设计假设是"模型会输出答案形态的内容，只是没包标签"。参考项目算术题满足该假设（答案=数字，宽松取数字即真正确）；本任务不满足（答案=中文数字串，宽松却允许"原数"通过）。

```
参考项目（算术）：输出 "85" → 宽松取数字 85 == 答案 → 真正确 ✅
本任务（转换）：  输出 "643" → 宽松取数字 643 == 原数 → 假正确 ❌（答案应是"六百四十三"）
```

**结论：宽松解析的安全边界 = 任务的答案形态必须与宽松规则形态一致。** 换任务时必须重新审计奖励解析器——这是从参考项目迁移方法论时最容易踩的隐性坑。
| 能力边界 | L6 两位数乘法学不动（8%→24%） | 1.5B 学得动 L6（0.38→0.62~0.66）；0.5B 不是学不动而是 hack |
| 方法论新增 | — | 严格/宽松双口径 + hack 归因分析 + 选题按模型自适应 |

### 6.3 工程教训

1. **RLVR 评估必须双口径**：宽松解析只能用于冷启动训练，评估必须看严格口径
2. **监控训练 reward 会骗人**：G1 训练 reward 全程 1.0 但严格 0.00——必须用验证集严格指标
3. **管道吞退出码**：`python | tee` 会让 CI 流程"假成功"，需 pipefail
4. **1.5B 全量 + 参考模型 = 24GB 卡的边缘**：19.26GB（think 模式）+ 3GB 参考模型 ≈ 23GB，batch 减半保持全局 batch 可解
5. **think 格式监控**：think_fmt 满分 ≠ 有实质思考，需检查 think 长度/内容
