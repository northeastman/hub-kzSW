# Qwen3.8-27B 与 DeepSeek-V4-Pro-0813 结构分析

这两个模型走的是两条完全不同的路：

- **Qwen3.8-27B**：可落地的 Dense 混合注意力小模型（带视觉）
- **DeepSeek-V4-Pro-0813**：1.6T MoE 的长上下文旗舰；相对 Preview 主要加了 DSpark

分析依据：`Qwen3.8-27B/config.json`、`Qwen3.8-27B/README.md`、`DeepSeek-V4-Pro-0813/config.json`、`DeepSeek-V4-Pro-0813/README.md`、`DeepSeek-V4-Pro-0813/inference/model.py`。

---

## 1. Qwen3.8-27B：Dense + 线性/全注意力混合

类型是**带视觉编码器的 Causal LM**，实现类仍是 `Qwen3_5ForConditionalGeneration`。`config.json` 和 Qwen3.6-27B **几乎同一套骨架**，3.8 的提升主要在训练和后训练，不是换结构。

| 项 | 取值 |
|----|------|
| 参数量 | **27B Dense**（不是 MoE） |
| 层数 / hidden | 64 / 5120 |
| FFN 中间维 | 17408，SwiGLU |
| 词表 | 248320 |
| 原生上下文 | **262K**，YaRN 可扩到约 1M |
| 模态 | 文本 + 图像 + 视频 |

### 1.1 层排布（核心）

64 层按 **3:1** 循环，一共 16 组：

```text
16 × ( 3 × (Gated DeltaNet → FFN)  +  1 × (Gated Attention → FFN) )
```

对应 `layer_types`：每 4 层里 3 层 `linear_attention`、1 层 `full_attention`。

- **Gated DeltaNet（线性注意力）**：长序列近似 O(n)，KV 不必按长度平方存。QK 16 头、V 48 头，head dim 128，短卷积核 4。
- **Gated Attention（全注意力）**：补回精确全局依赖。Q 24 头、KV 4 头（GQA），head dim 256，`attn_output_gate=true`，RoPE 只转 25%（64 维）。

长上下文主要靠线性注意力扛；每隔 4 层插一次全注意力，避免纯线性模型丢远程精确匹配。

### 1.2 其它结构点

- **原生多模态**：Vision Encoder 27 层、hidden 1152、patch 16，输出对齐到 5120；文本侧用 interleaved M-RoPE。
- **MTP**：1 层 multi-token prediction，加速解码。
- **没有 MoE**：容量全靠 Dense FFN，部署比 Pro 级 MoE 简单得多。

一句话：**用「多数线性注意力 + 少数全注意力」把 27B Dense 推到 256K 级上下文，并带上视觉。**

## 2. DeepSeek-V4-Pro-0813：稀疏注意力 MoE + DSpark

官方说明：骨架就是 V4-Pro Preview，**0813 多挂了一个 DSpark 投机解码模块**。

| 项 | 取值 |
|----|------|
| 总参 / 激活 | **约 1.6T / 49B** |
| 层数 / hidden | 61 / 7168 |
| 上下文 | **1M** |
| MoE | 384 路由 + 1 共享，每 token **激活 6** |
| 量化 | 专家 FP4，其余多为 FP8 |
| 模态 | 纯文本 |

### 2.1 注意力：滑动窗口 + 压缩 KV（CSA / HCA）

已经不是 V3 那种标准 MLA。每层都是：

1. **局部**：滑动窗口 **128**
2. **远程**：按 `compress_ratios` 压缩 KV，再做稀疏注意力

`compress_ratios` 的含义：

| 比值 | 机制 | 作用 |
|------|------|------|
| **4** | CSA + Indexer | 重叠窗口压缩，Indexer 选 **top-1024** 个压缩块 |
| **128** | HCA | KV 压得更狠，长上下文更省 |
| **0** | 只有窗口 | 不做压缩（主网最后一层，以及 DSpark 层） |

前两层是 128（HCA），后面大致 **4 和 128 交替**，最后一层为 0。Q 仍走低秩：`q_lora_rank=1536`；KV 实际是 **1 组、head_dim=512**（接近 MQA）。输出还有分组低秩 `o_groups=16, o_lora_rank=1024`。

这就是 README 说的：1M 上下文下，相对 V3.2 大约只要 **27% 单 token FLOPs、10% KV cache**。

### 2.2 残差：mHC，不是普通 skip

每层不用 `x + Attn(x)`，而是维护 **4 份** hidden（`hc_mult=4`），用 Sinkhorn 学混合权重再合并。深层 61 层时，信号更好传、也更稳。

### 2.3 MoE

- 全部 61 层都是 MoE（没有前几层 dense MLP）
- 前 **3 层 hash routing**（按 token id 定专家），后面才是分数路由
- 打分函数是 **sqrtsoftplus**，不是 V3 的 sigmoid
- 路由 `topk_method=noaux_tc`，`routed_scaling_factor=2.5`
- SwiGLU 有 `swiglu_limit=10`

### 2.4 0813 相对 Preview 真正多出来的：DSpark

config 里多了这几项：

```json
"dspark_block_size": 5,
"dspark_target_layer_ids": [58, 59, 60],
"dspark_markov_rank": 512
```

对应 `inference/model.py` 里的 `DSparkBlock`：

- 和主模型 **共用 embed / lm_head**，不是另训一个小草稿模型
- 取主网 **第 58–60 层** hidden，预测接下来 **5 个 token**
- 还有 **Markov head**（token 转移偏置）和 **confidence head**（接受/拒绝草稿）
- DSpark 注意力强制 `compress_ratio=0`，只看窗口 + 当前 draft block

所以 0813 的结构增量是：**同样的 V4-Pro 主干 + 权重内嵌的投机解码器**，用来把长生成（尤其 agent、max thinking）变快。

## 3. 对照：两条长上下文路线

| | Qwen3.8-27B | DeepSeek-V4-Pro-0813 |
|--|-------------|----------------------|
| 容量策略 | Dense 27B，全部激活 | MoE 1.6T，激活 49B |
| 长上下文 | Gated DeltaNet 线性注意力 | 窗口 128 + KV 压缩（CSA/HCA） |
| 精确匹配 | 每 4 层一次全注意力 | Indexer 选 top-k 压缩块 |
| 残差 | 标准残差 | mHC（4 路混合） |
| 视觉 | 有（27 层 ViT） | 无 |
| 解码加速 | MTP 1 层 | MTP + **DSpark（一次草拟 5 token）** |
| 部署 | 单卡/少卡友好 | 需要大集群 + EP/TP |
| 和前代关系 | 结构 ≈ Qwen3.6-27B | 结构 ≈ V4-Pro Preview，加 DSpark |

课程视角可以记成：

- **Qwen**：把序列建模从 softmax 注意力换成 **线性注意力为主**，用 Dense 小模型打长上下文和多模态。
- **DeepSeek**：注意力仍是 softmax，但 KV **压缩 + 稀疏选取**；容量交给 MoE；0813 再用 DSpark 把解码吞吐量拉上去。

继续读代码时：

- Qwen：看 `layer_types` 和 Gated DeltaNet
- DeepSeek：优先看 `Attention` / `Compressor` / `Indexer`，0813 再补 `DSparkBlock`
