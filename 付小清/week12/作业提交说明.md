# 第十二周作业：为 Agent 流程增加多轮对话能力

## 一、作业题目

在 `react_financial_agent` 的 ReAct Agent 基础上，增加**多轮对话**能力，使用户可以连续追问，Agent 能理解上下文（如「那五粮液呢？」）。

## 二、核心改造点

### 单轮 Agent（原版）

```
每轮用户提问 → 新建 messages = [system, user] → ReAct 循环 → Final Answer → 结束
下一轮提问 → 再次新建 messages，上一轮 Q&A 全部丢失
```

ReAct **内部**已有 Thought→Action→Observation 循环（第十一周内容），但**跨用户轮次**没有记忆。

### 多轮 Agent（本作业）

```
会话开始 → history = []
每轮:
  messages = [system, *history, new_user_question]
  ReAct 循环（工具调用 messages 仅在本轮内临时存在）
  Final Answer → history.append(user) + history.append(assistant)
下一轮 → history 带入，模型可理解追问
```

### 代码对比（关键差异）

**单轮**（`run_single_turn.py`）：

```python
messages = [
    {"role": "system", "content": SYSTEM_PROMPT},
    {"role": "user", "content": question},  # 只有当前问题
]
# ReAct 循环...
# 不保存 history
```

**多轮**（`conversation_agent.py`）：

```python
messages = [
    {"role": "system", "content": SYSTEM_PROMPT + multi_turn_hint},
    *self.history,                           # ← 跨轮历史
    {"role": "user", "content": question},
]
# ReAct 循环...
self.history.append({"role": "user", "content": question})
self.history.append({"role": "assistant", "content": answer})
```

## 三、设计要点

| 要点 | 说明 |
|------|------|
| 持久化什么 | 仅保存每轮的 `user 问题 + assistant Final Answer`，不保存中间 Tool/Observation |
| 为什么不存 Tool 消息 | 中间步骤 token 量大，且 Final Answer 已含结论；追问通常只需结论 |
| ReAct 与多轮的关系 | ReAct = 单轮内的工具循环；多轮 = 跨轮的用户对话循环，两者嵌套 |
| 会话管理 | `ConversationSession` 类，`reset()` 清空历史，`ask()` 处理一轮 |

## 七、预期效果

### 多轮模式（`run_multi_turn.py --demo`）

```
第1轮: 贵州茅台2023年的毛利率是多少？
  → company_lookup → financial_indicator → Final Answer: 91.96%

第2轮: 那五粮液呢？
  → 结合 history 理解「2023毛利率」→ 查五粮液 → 75.79%

第3轮: 两者差多少个百分点？
  → 结合前两轮 → calculator("91.96-75.79") → 16.17 个百分点
```

### 单轮对照（`run_single_turn.py --demo`）

```
第1问（独立）: 贵州茅台2023年的毛利率是多少？  → 正常回答
第2问（独立）: 那五粮液呢？  → 缺少上文，模型不知道「那」指什么，行为异常
```

## 八、与教学项目的关系

| 层级 | 项目 | 能力 |
|------|------|------|
| 单轮工具调用 | function_call_mcp_cli | 调一次工具即回答 |
| 单轮 ReAct 循环 | react_financial_agent | 单问内多步工具调用 |
| **多轮对话** | **work12（本作业）** | **跨轮保留 history，支持追问** |

## 九、技术要点

1. **两层循环**：外层 = 用户多轮对话；内层 = 每轮 ReAct 工具循环
2. **history 格式**：OpenAI messages 子集，仅 user/assistant 角色
3. **Prompt 增强**：System Prompt 追加多轮提示，引导模型结合 history 理解省略主语的追问
4. **token 管控**：当前未做截断；生产环境可对 history 做滑动窗口或摘要压缩

## 十、实际运行结果

使用上述 MaaS API（qwen3.7-plus）运行 `python run_demo_maas.py`，完整日志见 `demo_output.txt`。

### 实验 A：多轮对话（3 轮追问）

| 轮次 | 用户输入 | Agent 行为 | 结果 |
|------|----------|------------|------|
| 1 | 贵州茅台2023年的毛利率是多少？ | company_lookup → rag_search ×2 | 茅台毛利率 **92.11%**（2023年报第9页） |
| 2 | 那五粮液呢？ | 结合第1轮上下文 → company_lookup → rag_search | 五粮液毛利率 **81.92%** |
| 3 | 两者差多少个百分点？ | 引用 history → calculator(92.11-81.92) | 相差 **10.19** 个百分点 |

会话结束：`history` 共 6 条消息（3 轮 Q&A），总耗时约 67s。

### 实验 B：单轮对照（每问独立）

| 问次 | 用户输入 | Agent 行为 | 结果 |
|------|----------|------------|------|
| 1 | 贵州茅台2023年的毛利率是多少？ | 独立 ReAct | 毛利率约 **91.96%**（正常） |
| 2 | 那五粮液呢？ | 无 history，当作全新问题 | 输出五粮液全面财务概览，**未聚焦毛利率** |

单轮第 2 问耗时 67.7s，模型不知道「那」指上一轮的「2023毛利率」，验证了多轮对话的必要性。

### 结论

1. **多轮模式**能正确理解省略主语的追问（「那五粮液呢？」→ 查五粮液毛利率）。
2. **单轮模式**对同一追问给出冗长、偏离意图的回答。
3. 第 3 轮「差多少」在多轮模式下直接引用前两轮 Final Answer，无需用户重复数据。
4. 运行环境未安装 akshare 时，`financial_indicator` 失败，Agent 自动降级到 `rag_search`，仍完成任务。
