# 第十三周作业：渐进式加载执行 Skills 的 Harness

## 一、作业题目

写一套可以实现 **渐进式加载、执行 skills** 的 harness，对接本仓库 `week13/skills/` 下的 Agent Skills（`flash-card`、`baoyu-diagram`）。

## 二、背景：为何要渐进加载？

Cursor Agent Skills 采用 **Progressive Disclosure（渐进式披露）**：

| 层级 | 内容 | 何时加载 |
|------|------|----------|
| 索引 | `name` + `description`（frontmatter） | Agent 启动时可见 |
| 正文 | `SKILL.md` 完整指令 | 判定需要该 skill 后 `Read` |
| 资源 | `references/*.md`、`scripts/*` | 执行步骤引用时再读 |

若一次性把所有 skill 正文塞进 system prompt，token 浪费且干扰匹配。本作业 harness 显式实现上述三跳加载 + 执行。

## 三、核心架构

```
用户 query
    │
    ▼
[Stage 0] skill_registry.scan_skills_dir()
    │  输出: List[SkillMeta]（仅元数据）
    ▼
[Stage 1] skill_matcher.match_skill()
    │  输入: query + 元数据列表（不读正文）
    │  输出: skill_name（规则 或 LLM）
    ▼
[Stage 2] skill_loader.ensure_body()
    │  读取 SKILL.md 正文
    ▼
[Stage 3] skill_loader.load_resources_for_query()
    │  例: 「架构图」→ references/architecture.md
    ▼
[Stage 4] skill_executor.execute_skill()
    │  flash-card → make_flashcard.py
    │  baoyu-diagram → reference + LLM SVG（可选）
    ▼
输出文件 / 运行报告
```

## 四、与 Cursor Skills 的对应关系

| Cursor 行为 | 本 harness 模块 |
|-------------|----------------|
| System prompt 注入 `<available_skills>` | `build_index_prompt()` / Stage 0 |
| Agent 判断后 Read SKILL.md | Stage 2 `ensure_body()` |
| 按链接 Read reference / 运行 script | Stage 3 + Stage 4 |
| 用户规则「先 invoke skill 再行动」 | Stage 1 匹配 gating |


### 结论

1. **四阶段流水线**按设计工作：索引 → 匹配 → 渐进加载 → 执行。
2. **规则匹配**适合中英文混合的固定触发词（闪卡、画个图）；**LLM 匹配**适合英文 query（flash card）。
3. **baoyu-diagram** 的 reference 按图表类型按需加载，避免一次性读入全部 4 个 reference 文件。
4. flash-card 走确定性脚本链，LLM 仅用于匹配/生成 JSON（本 run 中 thrill 已有数据故直接复用）。
